How each round tends to test these five topics

Compiled from candidate reports of recent drives and from published section-wise breakdowns. Use it to decide where to spend your last week, not as a substitute for the official syllabus.

AssessmentReported shapeWhat it emphasisesPrioritise
TCS NQT & role tiers One to two problems in a short timed block at the entry tier; two to three problems with 60–90 minutes at the higher tiers. Exact output format, multiple test cases per problem and partial credit, so a solution that works for the common cases still scores. Number logic and series, array traversal, strings, matrices
Infosys SP / DSE About two coding problems in roughly 60 minutes, alongside MCQ sets on programming concepts and data structures. Medium to medium-hard difficulty with partial scoring. The coding block is the biggest filter for the premium tracks. Arrays with a twist, strings, sorting and searching, then harder dynamic-programming and graph ideas for the top track
Cognizant GenC / GenC Next A technical assessment split into two skill clusters: three sub-sections, six questions offered with three to be solved, in about 105–120 minutes. The problem-solving sub-sections are described as searching, sorting, string handling and arrays, and the round is an elimination stage. Sorting and searching, strings, arrays, pattern printing, number puzzles
Capgemini Roughly 20–25 pseudocode and output-prediction questions inside the programming and problem-solving block, followed by the coding stage. Tracing loops and arrays by hand, predicting printed output and reading complexity. No negative marking has been reported in recent drives. Number logic, pattern printing, array and string tracing by hand
Accenture A short timed coding block of around two problems inside the online assessment, with logic written on paper in the technical conversation. Clean, explainable logic more than clever optimisation, and being able to dry-run your own code. Numbers, arrays, strings
Wipro (Elite / NTH) A timed coding block of one to two problems, alongside aptitude and written sections. Direct statements over trick wording: transform, count or search through simple input. Numbers, strings, arrays
HCL, LTIMindtree, Tech Mahindra, Mphasis, IBM and similar Smaller logic-heavy blocks, usually one or two problems, often with the algorithm explained afterwards. Fundamentals and correct handling of edge cases rather than optimisation. Numbers, patterns, arrays, strings

Say the cost out loud

Interviewers score how you describe your approach as much as whether it runs. These are the sentences that work for each solution shape.

If your approach…Say thisWatch out for
Reads each element exactly onceO(n) time, O(1) extra spaceHidden nested work such as a lookup inside the loop
Compares every pairO(n²) time, O(1) space — and say that it will not scaleBeing asked for a linear version and not having one ready
Builds a frequency mapO(n) time, O(n) space, O(1) average lookup afterwardsCase folding and repeated counting passes
Sorts first, then scansO(n log n) for the sort plus O(n) for the scanDestroying the original order when the question needs it preserved
Searches sorted dataO(log n) time, O(1) space, iterativelyInteger midpoint overflow and off-by-one on the closing index
Searches an answer rangeO(log range) multiplied by the cost of one feasibility checkChoosing a check that is not monotonic over the range
Keeps a moving windowO(n), because each element enters and leaves the window onceShrinking the window before updating the best answer
Uses a running total or prefix sumO(n) to build, O(1) per range queryHandling the empty prefix when a range starts at the first element
Uses two pointers on sorted dataO(n) after the sort, O(1) extra spaceMoving both pointers at once and skipping valid pairs
Scans once keeping a local bestO(n) time, O(1) space, single passRestarting the running value at the wrong element
Precomputes counts into a small arrayO(n + k) time where k is the range of valuesUsing it when the value range is unbounded

The same twelve mistakes, every year

These cost marks far more often than wrong logic does, because they are invisible until the hidden test cases run.

⚠

Input & format

  • Printing an extra prompt text or a trailing space that the expected output does not contain.
  • Reading the whole line when the input has several space-separated values, or the reverse.
  • Assuming the number of test cases is fixed at one.
  • Assuming values are positive: zero, the empty input and negative numbers appear in hidden cases.
⚠

Loops & bounds

  • Off-by-one in the last row, last column or last index of a loop boundary.
  • Using the original length after modifying the input inside the loop.
  • Nested loops that run one iteration too many and print an extra blank line.
  • Not resetting an accumulator between test cases.
⚠

Values & types

  • Overflow on factorials, powers or products — use a wide integer type or reduce with a modulus.
  • Integer division where a decimal result is expected, or the reverse.
  • Comparing characters by their code instead of after normalising case.
  • Duplicate output when an element is reported once per occurrence instead of once in total.
