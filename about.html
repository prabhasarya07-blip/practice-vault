How to use

A reading-and-writing loop, not a solution library

If you cannot state the algorithm in plain steps, you cannot write the code under time pressure — so every page here stops where the thinking begins.

The loop

Repeat this for each problem. It takes about ten minutes and beats an hour of reading finished solutions.

Step 1

Read only the statement

Note the input shape, the output shape and the constraints. Say out loud what the smallest and largest cases look like.

Step 2

Guess the pattern

Traversal, two-pointer, window, hashing, recursion, matrix? Naming the pattern before you look is the skill being built here.

Step 3

Write steps, then code

Numbered plain steps first, then the code in the language you will be tested in. Keep the two separate and honest.

Step 4

Compare, then mark

Open the problem page and compare your steps against the listed algorithm and traps. Tick “practised” only if they matched in substance.

Step 5

Come back cold

A day later, redo the problem from memory with hints hidden. That second pass is what converts understanding into recall.

How the bank was assembled

Nothing here is a random dump of popular interview questions. The list was built topic by topic from what candidates report actually appearing in fresher assessment rounds and technical conversations.

  • Company question lists and placement papers. Public compilations of questions reported from recent hiring drives were collected first, then grouped by topic instead of by company.
  • Assessment structure write-ups. Section-wise breakdowns for the major hiring programmes were used to weight how much space each topic gets here — which is why arrays and strings carry the most problems, and why pattern printing is not treated as a toy.
  • Interview-experience reports. Repeatedly recurring follow-ups and traps became the “follow-up variations” and “where candidates lose marks” sections on each problem page.
  • De-duplication. Questions that are the same idea with a different storyline were merged into one entry with variations noted, so the bank measures breadth rather than repetition.
  • Ordering by dependency. Topics and variants are sequenced so each new problem needs only the ideas already introduced earlier in the bank.
→ Frequency labels indicate how often a style has been reported, not a guarantee. Use them to order your practice, and always read the official syllabus for the drive you are targeting.

What is in scope, and what is not

Five topics, chosen because they appear in nearly every fresher assessment and because you can fully master them in a few weeks.

In the bankDeliberately out of scope
  • Number logic, divisibility, bases, series
  • Pattern printing in stars, numbers and alphabets
  • Arrays, running totals, two-pointer, windows, hashing, matrices
  • Strings, classification, frequency maps, anagrams, tokenising
  • Sorting algorithms and searching, including binary search variants
  • Linked lists, stacks, queues, trees, heaps and graphs as full topics
  • Dynamic programming and greedy proof-heavy problems
  • System design, database and aptitude questions
  • Language trivia and framework-specific behaviour
  • Finished code and expected outputs — by design, not by omission

The advanced structures above matter for product-company and specialist-track interviews, but they are not what decides a fresher assessment or a first technical round, and learning them before these five topics is a common way to lose preparation time.

Questions people ask about this site

Do I need to create an account?

No. There is no sign-up, no email, no login and no tracking. Open it, use it, close it.

Why are there no answers or solutions?

Because a solution you read is a solution you cannot reproduce. You get the pattern, the technique and the algorithm as steps — the parts an interviewer wants to hear — and you produce the code yourself.

Is the code written in one specific language?

No. The algorithm steps are language-neutral, so the same page works whether you will be tested in C, C++, Java or Python. Details that differ between languages, such as integer width or string handling, are flagged in the traps section.

Where is my progress stored?

In your browser's local storage, on your machine. The “mark as practised” ticks and your theme choice are the only things saved, and clearing your browser data removes them.

Can I use the drill sheet for group practice?

Yes. Generate a sheet, hide the hints and print it. Give the same sheet to a group and compare the algorithms people write before anyone touches a keyboard.

Can I use this offline?

Yes. Save the folder and open the pages locally — there is no server, no build step and no external request anywhere in the site.
